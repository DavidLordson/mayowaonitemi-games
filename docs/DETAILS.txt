3. ARCHITECTURE
======================================================================
Plain HTML/CSS/JS front end (no build step) + one Netlify Function + Netlify
Blobs storage. Phones poll the server about once a second (5s when the tab
is hidden). No database, no websockets.

Files:
  public/index.html        All screens: home, join, room lobby, crossword,
                           board-game container, dialogs.
  public/style.css         All styles (crossword, lobby, Ludo board, Whot cards).
  public/app.js            App shell: rooms/logins, polling, lobby, crossword
                           play, menus; mounts Ludo/Whot views.
  public/crossword.js      buildPuzzle(): numbering + words from a grid.
  public/ludo.js           Ludo board UI (15x15 CSS grid, tokens, two dice).
  public/whot.js           Whot table UI (cards drawn with CSS/SVG).
  public/puzzles/*.json    Book crossword(s); index.json lists them.
  lib/generator.mjs        Random criss-cross crossword generator.
  lib/words.mjs            Word bank (~426 [WORD, clue] pairs) for generator.
  lib/games/ludo.mjs       Ludo rules (pure functions, run on server).
  lib/games/whot.mjs       Whot rules (pure functions, run on server).
  netlify/functions/room.mts  The whole backend at /api/room.
  scripts/validate-puzzles.mjs  Book puzzle numbering check.
  scripts/check-generator.mjs   Generates puzzles and checks them.
  scripts/check-games.mjs       Plays hundreds of random Ludo/Whot games.
  netlify.toml             publish=public, functions dir, build=npm run validate.
  README.md                Short overview.

Blob store "crossword" (strong consistency), keys:
  rooms/<room>/info              { name, members, meta, generated }
       members: { pid: { name, color, tokens:[sha256 of device tokens], joinedAt } }
       meta:    { gameId, game: "lobby"|"crossword"|"ludo"|"whot", puzzleId?, startedAt }
                (old rooms may lack `game` => treated as crossword)
  rooms/<room>/invites/<code>    { kind: "member"|"device", pid?, expires, by }
  games/<gameId>/players/<pid>   crossword letters { cells:{"r,c":[letter,t]}, cursor, seen }
                                 (also used as presence heartbeat for all games)
  games/<gameId>/puzzle          generated crossword JSON
  games/<gameId>/state           Ludo / Whot game state

API (/api/room). Auth = header "Authorization: Bearer <device token>".
  GET  ?room=X                 room state (+ game view for Ludo/Whot)
  GET  ?room=X&puzzle=1        generated puzzle for current game
  POST action=create           (no auth) make room -> {room, pid, token}
  POST action=inviteInfo/join  (no auth) use an invite code
  POST action=edit             crossword letters / cursor / heartbeat
  POST action=new              start game {game, puzzleId?, fromGameId}
  POST action=play             Ludo/Whot move {gameId, move}
  POST action=invite           make link {kind: member|device}
  POST action=profile          change name/colour
  POST action=logout           remove this device's token

Key design decisions:
- Crossword sync: each player's device writes only its OWN blob, so two
  people typing at once never collide; readers merge per cell, newest wins.
- Ludo/Whot: rules run on the server (dice, shuffling, turn checks) with a
  conditional (etag) write; Whot only sends each player their own hand.
- Logins: each device holds a random secret token in localStorage
  ("cw-rooms"); the room stores only its hash. No passwords/accounts.
- Players for Ludo/Whot = all room members (max 4), seated in JOIN ORDER,
  so seats are stable game to game (room creator first).

4. FEATURES (current behaviour)
======================================================================
Rooms & logins
- Home page: list of your rooms on this device + "Create a private room".
- ⋯ menu: Invite someone (one-time link, 7 days), Log in on another device
  (one-time link, 30 min, logs in as the SAME player), Check/Reveal (crossword
  only), Change name/colour, Games, Log out of this room.
- Opening a room link without a login shows "This room is private".
- Max 8 members per room.

Lobby (added last)
- Opening a room, or tapping ⌂, shows the room LOBBY: "Continue ›" for the
  game in progress + cards for Ludo, Whot, Crossword (random) and book puzzles.
- New rooms start in the lobby (meta.game = "lobby").
- If you're waiting in the lobby and someone starts a game, you're pulled in.
- "← All my rooms" goes back to the home page.

Crossword
- Book puzzle "Puzzle 1" (13x13) transcribed from David's photo and fully
  solved from crossings. Notable answers: 12A WALE (not WELT), 27D IN (not UN),
  29A PHASIS, 15A AMBIGUOUS, 8D DYSLOGISTIC, 16D GESTICULATE.
- Random crosswords: criss-cross style, ~28 words, built on the server from
  lib/words.mjs, titled "Puzzle #N" per room.
- Live typing, letters in each player's colour, partner's cursor/word shown,
  custom on-screen keyboard, Check puzzle, Reveal letter, "Solved!" banner.

Ludo (house rules agreed with David)
- TWO dice. Use each die once on any token (split or combine).
- A 6 on a die brings a token out of the yard.
- Double 6, a capture, or getting a token home = another roll.
- Start squares and star squares are safe. Exact roll to get home.
- 2 players: each plays TWO opposite houses — first member (David/Onitemi)
  = red + yellow, second (Mayowa) = green + blue. Win = all 8 tokens home.
  Own two houses never capture each other.
- 3-4 players: one house each.

Whot (Nigerian rules, David's house rules)
- 54-card deck, 5 cards dealt.
- 1 Hold on (play again), 2 Pick two, 5 Pick three, 8 Suspension,
  14 General market (everyone else picks 1, you play again),
  20 Whot (wild, call a shape).
- Pick two CAN be blocked with your own 2; blocks stack (2 -> 4 -> 6...);
  whoever can't/won't block taps the market to pick and loses their turn.
- Pick three cannot be blocked (could be changed if David wants).
- Market empty after reshuffle: lowest hand total wins.
