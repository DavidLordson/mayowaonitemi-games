PROJECT NOTES (short) — read this only; open docs/DETAILS.txt just when a task needs it.

WHAT: "Games Together" — private site where David (aka Onitemi) and Mayowa play
Crossword, Ludo, Whot live on separate phones. User wants short, curt replies.

WHERE
- Repo DavidLordson/mayowaonitemi-games, branch claude/optimistic-allen-tmbuoj (only branch).
- Live: https://mayowaonitemi-games2.netlify.app (Netlify site id d81e89ce-5929-44b3-913c-f80bb19fc60e).
- Push to the branch = auto deploy (~1 min). Build runs `npm run validate` (tests).
- Cloud sessions can't reach *.netlify.app; check deploys via Netlify MCP get-project.

HOW IT WORKS
- Static front end in public/ + one function netlify/functions/room.mts (/api/room)
  + Netlify Blobs. Phones poll ~1s.
- Rooms are private: device token in localStorage, invite links (7 days), device-login
  links (30 min, same player). Opening a room shows a lobby (Continue / pick a game).
- Game rules run on the server: lib/games/ludo.mjs, lib/games/whot.mjs.
  Crossword generator: lib/generator.mjs + lib/words.mjs (~426 words).
- Ludo is 3D: public/ludo3d.js draws public/models/ludo_set.glb (made in Blender) with
  three.js r169 vendored in public/vendor/three (import map in index.html). Falls back
  to the flat CSS board if 3D fails.
- Ludo vs computer: lobby card -> new game with players [you, "cpu"]. The bot
  (botMove in lib/games/ludo.mjs) plays on the server, one action per request, 600 ms
  apart (botStep in room.mts); clients poll every 650 ms during its turn.

HOUSE RULES
- Ludo: two dice, each die used once on any token; 6 brings a token out; double 6 /
  capture = roll again (token home does NOT). 2 players: first member red+yellow, second
  green+blue, all 8 home to win.
- Whot: 1 hold on, 2 pick two (blockable with a 2, stacks), 5 pick three (not
  blockable), 8 suspension, 14 general market, 20 whot (call shape).
- Crossword: book Puzzle 1 + random puzzles.
